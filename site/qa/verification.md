# 3D試作の検証

2026-10-21 / 計画の第1段階「入口 → 自己紹介」

## 自動確認

- `npm test`: スクロール状態のテスト3件、画像・CSS・スクリプト参照、ページ内リンク、ID・画像ラベルの検査。
- テスト内容: 端末が開いてから通過する順序、前進と逆再生での状態一致、進捗の範囲外処理、カメラ補間の連続性。
- `npm run build`: Viteの本番用ビルド。

## ブラウザ確認

- 320×740、390×844、768×1024、1280×720で横スクロールなし。
- 端末の外装が開く → 画面の奥へ進む → 作業机が組み上がる → 自己紹介が現れる。
- 逆スクロールと章へのリンク、自己紹介の直接URL、途中位置での再読み込み。
- 「演出を減らす」でCanvasを解放し、本文・イラストを表示。3Dの再開も確認。
- OSの `prefers-reduced-motion: reduce` で本文を表示し、Canvasを作成しない。
- WebGL context lossを意図的に発生させ、静的表示への回復と案内を確認。検証後は通常状態へ復帰。
- キーボードから章へ移動すると、表示された章にフォーカスを移す。
- JavaScript無効時もCSS・本文・リンク・代替イラストを表示する。
- 本番用ビルドを別のローカルサーバーで配信し、3D描画と画像読み込みを確認。初期の影描画APIに関する警告は修正済みで、本番ページでの新規エラー・警告なし。

## 描画負荷と制約

- 描画ポリゴン数は入口約1.9万、作業机約4万。画面比率に応じて構図と描画解像度を変更。
- 開発時の描画コール間隔は、PCブラウザと390px幅のエミュレーションでおおむね毎秒59〜60回。実機のGPU完了時間や安定した60fpsを保証する測定ではない。
- スクロール・リサイズ・補間が止まると追加の3D描画も停止する。
- ビルドのThree.js描画チャンクは約545KB（gzip約138KB）。Vite既定の500KB警告は残るが、描画コードは動的ロードし、演出軽減時は読み込まない。

未検証: 実機iOS/Safari・Android、公開環境。制作物・つながる章は、最初の2場面の世界観確認後に追加する。
